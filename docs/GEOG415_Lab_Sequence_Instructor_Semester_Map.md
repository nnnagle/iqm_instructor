GEOG 415 Lab Sequence
Semester Map for Instructors, TAs, and Future AI Agents
This is a planning map, not a set of student-facing lab instructions. For every lab session it answers three questions: (1) What can we assume students already know or possess? (2) What must happen in this session? (3) What should exist when they leave? Each module ends in one graded deliverable.
Do not treat labs as stand-alone exercises. Every session opens the existing team R project and advances the same semester-long tool.
Course-wide assumptions
Project: a Tennessee census-tract Community Primary Care Priority Rating built from public data.
Computing: R/RStudio; core packages should stay small (tidyverse, sf, ggplot2, plus only what is needed for a specific task).
Students begin the project at speed zero. Lab 1 establishes the R project, folders, scripts, naming, and first data import.
Raw data remain unchanged. Every transformation, join, exclusion, score, model, figure, and table is generated by code.
Teams work on one cumulative project. The six module deliverables become parts of the final client report and technical appendix.
Geographic methods enter immediately and recur: identifiers/joins, rates, choropleths, point-area representation, proximity, scale/aggregation, residual mapping, and simple spatial diagnostics.
The late-semester peer audit tests reproducibility and whether implementation matches intended use; it is not a contest to find exotic failure modes.

Module 1 — Data and Measurement
Module question: Where did these numbers come from?
Graded module deliverable: Data Provenance & Measurement Audit
What that deliverable should contain: Project purpose and intended use; source inventory; data dictionary; Analytic Dataset v1; first maps; explanation of the first service-access measure and its limitations.
Lab 1A — R from zero: first script, first data, first map
Entering this lab: what students already know / possess
No semester project files yet.
Assume zero prior knowledge of R or RStudio. Students may never have opened R, run a command, created an object, or seen a data frame.
Conceptually, students are beginning to distinguish a real-world concept from a variable used to measure it.
This lab must accomplish
Orient students to R versus RStudio: Console, Source/script pane, Environment, Files/Plots/Help, and the idea that code is written in a script and then executed.
Teach the minimum R vocabulary needed to work: assignment (<-), objects, function calls, arguments, vectors/data frames, and how to read an error message without panic.
Create the RStudio Project and a simple stable folder structure; create 00_setup.R and 01_get_data.R. Explain why projects and relative paths matter.
Introduce packages with library(); load tidyverse, sf, and ggplot2, emphasizing what each is for rather than package mechanics.
Use instructor-provided or highly scaffolded code to read one simple tract-level table and Tennessee census-tract geometry. Teach students to inspect objects with View(), names(), glimpse(), head(), and nrow().
Introduce the data-frame workflow through only the verbs needed today (primarily mutate() and a simple pipe). Construct one meaningful rate from a numerator/denominator pair and contrast rates with counts.
Perform a highly scaffolded first join using GEOID. Teach the idea of a key and require a simple check of row counts and unmatched cases; do not expect mastery of joins yet.
Create the first choropleth with a mostly supplied ggplot2/sf template. Students should change the mapped variable/title and understand the major pieces of the code rather than write the map from memory.
Start README.md with purpose, geography, data location, and script run order.
Students should leave with: A functioning R project; tract geometry joined to at least one public indicator; one reproducible saved map; README started.
Lab 1B — Build the measurement system: metadata, facilities, and access
Entering this lab: what students already know / possess
Students have exactly one lab of R experience. They can open the RStudio Project, run code from a script, recognize assignment/function calls/data frames, inspect an object, follow a simple pipe, and rerun the scaffolded join/map workflow.
They have one tract-level indicator and have seen the distinction between counts and rates, but R syntax and data manipulation are still new and need repeated scaffolding.
They have a README but not yet a mature metadata/provenance system.
This lab must accomplish
Add the small set of candidate ACS indicators for need/access barriers.
Import a public point dataset for relevant primary-care service locations.
Map facility points with tract polygons; discuss point versus areal representation.
Construct one deliberately simple access measure such as tract-centroid distance to nearest service site.
Inspect large/rural tracts where centroid distance is a weak proxy and document why.
Inspect variable definitions, denominators, vintages, missingness, and margins of error.
Build source inventory and data dictionary in metadata/.
Write a plain-language statement for each key variable: what it measures, what it does not, and any geographic caveat.
Students should leave with: Analytic Dataset v1; first access variable; source inventory; data dictionary; annotated maps; enough material to assemble the Module 1 deliverable.
Module 2 — Association and Comparison
Module question: What varies with what?
Graded module deliverable: Exploratory Analysis & Rating Specification
What that deliverable should contain: Selected indicators and keep/drop rationale; key EDA figures/maps; Rating v0.1; exact scoring rules; one sensitivity comparison showing how a reasonable design choice changes results.
Lab 2A — Explore distributions, associations, and geographic contrasts
Entering this lab: what students already know / possess
Students have a clean tract-level dataset with candidate need/access variables and a facility-access measure.
They can make basic maps and ordinary plots in ggplot2 and understand variable definitions/provenance.
They have not yet decided which indicators belong in the final rating.
This lab must accomplish
Create distributions and concise summaries for all candidate indicators.
Create scatterplots/correlations for plausible pairs and discuss redundancy versus distinct information.
Map at least two indicators and identify geographic clustering/contrasts.
Compare at least one relationship across a geographic context such as metro/nonmetro or broad region.
Demonstrate ecological fallacy and/or MAUP through a compact tract-versus-county comparison tied to project variables.
Identify outliers and unexpected cases by place, not only by row number.
Narrow the indicator set and record explicit reasons for keeping or dropping each candidate.
Students should leave with: Exploratory figure set; evidence about redundancy and geographic context; defensible short list of rating inputs.
Lab 2B — Construct and challenge Rating v0.1
Entering this lab: what students already know / possess
Students know the distributions, relationships, and geographic behavior of the candidate inputs.
They understand that changing geographic scale can change a relationship.
They have a short list of indicators but no composite score yet.
This lab must accomplish
Define the direction of each input: what makes priority increase or decrease.
Standardize inputs with an explainable method (prefer percentiles or z-scores).
Construct an equal-weight baseline score before considering alternatives.
Map the rating and inspect highest-, lowest-, and surprising-score tracts.
Decompose scores for several surprising places to see which components drive them.
Change one reasonable design choice (weight, inclusion, or scaling) and quantify rank changes.
Write scoring_specification.md: inputs, formulas, directions, weights, missing-data rule, and intended interpretation.
Ask explicitly whether the score measures primary-care priority or mostly reproduces another construct such as poverty or rurality.
Students should leave with: Rating v0.1; rating map; transparent scoring specification; sensitivity comparison; enough material for Module 2 deliverable.

Module 3 — Uncertainty and Evidence
Module question: How sure are we?
Graded module deliverable: Uncertainty & Evidence Brief
What that deliverable should contain: Maps/diagnostics of input uncertainty; rating-stability analysis; one external-evidence result with effect size and uncertainty; interpretation of what the evidence supports and does not support.
Lab 3A — Put uncertainty on the map
Entering this lab: what students already know / possess
Students have a functioning Rating v0.1 and understand its components and scoring choices.
They know ACS inputs include margins of error, but have not yet incorporated that uncertainty into interpretation.
They can map tract-level values and compare geographic contexts.
This lab must accomplish
Pair selected ACS estimates with margins of error.
Calculate a simple relative-uncertainty diagnostic where sensible and discuss pathological cases.
Map uncertainty separately from the substantive estimate.
Compare uncertainty by population size and/or geographic context.
Identify tracts whose rating depends on especially uncertain inputs.
Distinguish true geographic variation from uncertainty in the measurement.
Add uncertainty flags/diagnostics to the processed data rather than silently excluding difficult cases.
Students should leave with: Input-uncertainty maps and tract-level uncertainty diagnostics that can condition later interpretation.
Lab 3B — Test rating stability and compare with external evidence
Entering this lab: what students already know / possess
Students know where key inputs are relatively precise or imprecise.
They have Rating v0.1 and can recompute it from code.
They understand sampling variability/interval logic sufficiently to interpret uncertainty.
This lab must accomplish
Recalculate scores/ranks under simple plausible high/low input scenarios or a light instructor-scaffolded simulation.
Identify tracts whose rank/category is stable versus unstable.
Introduce one external outcome not used to build the rating.
Plot rating versus external outcome and fit/compute one simple comparison or association.
Report effect size, interval/standard error, and p-value as appropriate, in that interpretive order.
State what this external evidence supports about the intended rating and what it cannot establish.
Update scoring documentation if the stability analysis reveals a needed caveat or rule.
Students should leave with: Rating-stability results; one external-evidence result; client-ready language about uncertainty and evidential limits.
Module 4 — Statistical Models
Module question: How do we describe relationships?
Graded module deliverable: Model & Geographic Diagnostics Report
What that deliverable should contain: Simple and multiple regression results; interpretation; diagnostic figures; residual map; optional simple spatial autocorrelation result; model card with intended and inappropriate interpretations.
Lab 4A — Simple regression, diagnostics, and residual geography
Entering this lab: what students already know / possess
Students have an external outcome and know its bivariate association with the rating.
They understand effect size, uncertainty, and significance at an introductory level.
They have not yet used regression as the central framework for modeling the relationship.
This lab must accomplish
State the modeling question before fitting lm().
Fit one simple linear regression linking the rating or a major component to the external outcome.
Interpret intercept, slope, fitted values, residuals, uncertainty, and practical meaning.
Produce essential diagnostic plots and connect each to a model assumption.
Join residuals back to tract geometry and map them.
Investigate several large residuals as actual places.
Ask whether errors cluster geographically and what missing process might explain the pattern.
Save model object, tidy coefficient table, diagnostic figures, and residual map by code.
Students should leave with: A reproducible simple model, diagnostics, coefficient table, and residual map; students see model failure as geographically informative.
Lab 4B — Multiple regression and a modest spatial diagnostic
Entering this lab: what students already know / possess
Students can fit and interpret simple linear regression and understand residuals.
They have a residual map and specific places where the simple model fails.
They understand confounding conceptually from earlier association work.
This lab must accomplish
Fit a multiple regression with only a few substantively justified predictors.
Compare coefficients with bivariate results and interpret them conditionally.
Introduce a transformation or interaction only if motivated by a visible problem.
Compare model fit and residual behavior across specifications.
If feasible, compute Moran's I on residuals with an instructor-supplied neighbor workflow; emphasize interpretation, not weights-matrix mechanics.
If Moran's I is omitted, conduct a structured geographic residual assessment.
Create/update a model card: purpose, response, predictors, assumptions, known breakdowns, appropriate interpretation, inappropriate interpretation.
Students should leave with: A modest final explanatory model, geographic diagnostics, and model card; enough material for Module 4 deliverable.

Module 5 — Explanation and Prediction
Module question: What question is this model answering?
Graded module deliverable: Reproducible Model Package
What that deliverable should contain: Frozen rating/model version; held-out predictive evaluation; geographic error analysis; README; script order; data/metadata; scoring specification; model card; intended-use statement; specified outputs for peer reproduction.
Lab 5A — Prediction, held-out evaluation, and geographic error
Entering this lab: what students already know / possess
Students understand linear/multiple regression, residuals, diagnostics, and that association/explanation differs from causation.
They have a documented rating and explanatory model.
They have not yet evaluated a model on data held out from fitting.
This lab must accomplish
Define a simple binary prediction target from the external outcome using an approved substantive threshold.
Create a reproducible train/test split with a fixed seed.
Fit logistic regression and generate held-out predicted probabilities.
Evaluate with a small number of understandable metrics; avoid a metric zoo.
Examine false positives/false negatives or prediction error across geographic contexts.
Map errors or classifications.
Optionally fit one highly scaffolded random forest and compare held-out performance and interpretability.
Ask whether improved prediction, if any, changes what the model can appropriately be used for.
Students should leave with: Held-out prediction results; geographic error analysis; clear distinction between explanatory and predictive claims.
Lab 5B — Freeze, document, and hand off the project
Entering this lab: what students already know / possess
Students have a mature rating, explanatory model, predictive evaluation, maps, metadata, and several rounds of sensitivity/diagnostic evidence.
They have practiced reproducible scripts but have not yet had to package the whole project for a stranger.
They understand the intended use of their tool well enough to state it explicitly.
This lab must accomplish
Freeze the rating/model version the team is prepared to defend; stop feature creep.
Clean script order, relative paths, dependencies, and generated outputs.
Ensure a fresh-session run can rebuild key products from the documented starting point.
Finalize README, data dictionary, scoring specification, model card, and source inventory.
Specify one figure and one statistical result the receiving team must reproduce.
Write a concise intended-use statement plus examples of out-of-scope uses.
Create a handoff checklist and package with no oral explanation required.
Students should leave with: A complete Reproducible Model Package ready for peer implementation; this package is the Module 5 graded deliverable.
Module 6 — Reproduction, Geography, and Fitness for Use
Module question: What happens when another analyst actually uses it?
Graded module deliverable: Independent Audit, Response & Final Use Guidance
What that deliverable should contain: Audit of another team's package; response to received audit; documented revisions; final geographic/scale stress test; final use/safeguard/consequence guidance; corrected technical package.
Lab 6A — Reproduce and stress-test another team's tool
Entering this lab: what students already know / possess
Students know how a complete rating/model workflow is supposed to be documented because they just packaged their own.
They can run R scripts, inspect data/metadata, interpret model outputs, examine geographic error, and perform simple sensitivity analyses.
They have not yet worked as independent users of another team's workflow.
This lab must accomplish
Open another team's package without oral help.
Attempt to reproduce the specified figure and statistical result.
Log every broken path, undocumented assumption, ambiguous variable, discrepancy, and manual step.
Compare the implemented score/model with the stated intended use: does the implementation operationalize what the authors claim?
Run a small set of prescribed stress tests (for example weight, threshold, missingness, geographic subgroup, or scale).
Classify findings: coding bug, documentation failure, measurement mismatch, sensitivity, geographic failure, or out-of-scope use.
Write critique as actionable evidence rather than adversarial commentary.
Students should leave with: A concrete independent audit that tests both reproducibility and intention-versus-implementation.
Lab 6B — Respond, revise, and define the tool's domain of use
Entering this lab: what students already know / possess
Students have completed an audit of another team and received an audit of their own.
They now possess external evidence about whether their package is reproducible and whether another analyst interpreted it as intended.
They have all technical content needed for the final report; remaining work is revision, synthesis, and judgment.
This lab must accomplish
Classify each major criticism received: valid flaw, documentation problem, substantive limitation, reasonable disagreement, or out-of-scope use.
Revise code, documentation, rating, model, or interpretation where justified.
Explicitly defend choices not changed.
Conduct one final geographic/scale analysis prompted by the audit or by model-error patterns.
Finalize the technical appendix/package for the analyst who must run and update the tool.
Develop client-facing guidance: useful decisions, inappropriate uses, safeguards/complementary evidence, and plausible intended/unintended consequences.
Identify specific project experiences students can later draw on in the individual assessment/reflection.
Students should leave with: Analytic work essentially complete: corrected package, documented audit response, final geographic stress test, and evidence base for the group report and individual reflection.

What future instructors / TAs / AI agents should not change casually
Do not replace the cumulative project with disconnected weekly datasets unless there is a compelling reason.
Do not add statistical or spatial methods merely because they are available in R; methods must solve a problem students have already encountered.
Do not allow the rating to become an opaque index with many variables or elaborate weighting.
Do not delay geographic reasoning until Module 6.
Do not turn the random forest into a machine-learning survey; it is optional and mainly a comparison point for prediction versus interpretability.
Do not let the peer audit become a search for clever attacks; it tests reproducibility, fitness for intended use, plausible sensitivity, and geographic failure.
Do not accept generic reflection at the end. The individual reflection must cite specific course work and explain what changed in the student's practice or thinking.
